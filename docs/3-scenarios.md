# Нефункциональные требования и сценарии

| Код | Требование |
| --- | --- |
| НФТ-01 | При каталоге из 10 000 активных товаров, 30 000 вариантов и нагрузке 50 одновременных пользователей не менее 95% ответов API каталога занимают не более 2 секунд. Проверка: 10 минут запросов каталога и фильтров, без учёта передачи фотографий; сервер — 4 vCPU, 8 ГБ RAM и SSD. |
| НФТ-02 | Весь обмен между браузером и сервером выполняется по HTTPS. Пароли хранятся в виде стойких хешей с солью; исходный пароль не сохраняется. |
| НФТ-03 | Сервер выдаёт заказ покупателю только при совпадении userId с владельцем. Склад видит состав, телефон и адрес для отправки. Контент-менеджер не получает данные заказов. Администратор управляет учётными записями, но не получает доступ к заказам только из-за своей роли. Запрещённый запрос не возвращает содержимое заказа. |
| НФТ-04 | При ширине экрана 360, 768 и 1440 пикселей каталог, корзина и оформление доступны без горизонтальной прокрутки страницы. |
| НФТ-05 | Резервная копия базы создаётся раз в сутки. При контрольном восстановлении допустима потеря не более 24 часов данных; восстановление должно занять не более 4 часов. |

## СЦ-01 Оформление заказа

Участник: покупатель. Предусловия: выполнен вход, в корзине есть товары.

1. Покупатель открывает корзину и проверяет размер, цвет и количество.
2. Указывает телефон и адрес доставки.
3. Нажимает «Оформить заказ».
4. Система проверяет обязательные поля, актуальные цены и доступные остатки.
5. В одной транзакции система проверяет и резервирует остатки, сохраняет заказ с состоянием «Новый» и фиксирует цены. Повтор с тем же ключом оформления возвращает тот же заказ.
6. Покупатель видит номер, сумму и кнопку оплаты.

Если данных не хватает, система выделяет незаполненное поле. Если товара недостаточно, заказ не создаётся, остаток не меняется, покупатель получает предложение изменить корзину. Если цена изменилась, система показывает новую сумму и запрашивает повторное подтверждение.

## СЦ-02 Оплата заказа

Участники: покупатель и платёжный сервис. Предусловия: есть заказ «Новый» и резерв товара.

1. Покупатель нажимает «Оплатить».
2. Система создаёт попытку оплаты и переводит её в состояние «Ожидает».
3. Покупатель вводит платёжные данные на стороне платёжного сервиса.
4. Сервис передаёт серверу магазина подтверждение.
5. Магазин проверяет подлинность сообщения, номер заказа, сумму и валюту. Первое успешное сообщение переводит попытку в «Успешна», а заказ — в «Оплачен». Повторное сообщение с тем же идентификатором не меняет данные и не создаёт ещё одно письмо.
6. Система ставит уведомление в очередь отправки; покупатель видит результат в кабинете.

При отказе оплаты попытка получает состояние «Отклонена», заказ остаётся «Новый». Можно повторить оплату. Возврат покупателя со страницы сервиса сам по себе не подтверждает оплату.

## СЦ-03 Отмена заказа

Участник: покупатель. Предусловие: заказ принадлежит этому покупателю.

1. Покупатель открывает заказ и выбирает отмену.
2. Система разрешает отмену только для своего заказа «Новый», если нет попытки оплаты «Ожидает» или «Успешна». Проверка состояния и освобождение резерва выполняются одной транзакцией.
3. При успешной проверке заказ получает состояние «Отменён», а резерв товара освобождается.
4. Покупатель видит обновлённое состояние.

## СЦ-04 Отправка заказа

Участник: сотрудник склада. Предусловие: заказ оплачен.

1. Сотрудник открывает заказ и переводит его в «Собирается».
2. Комплектует позиции с указанными размерами и цветами.
3. Вводит номер отслеживания и отмечает отправку.
4. Система переводит заказ в «Отправлен», списывает зарезервированный товар и ставит письмо в очередь.

Без номера отслеживания переход в «Отправлен» запрещён. Неоплаченный заказ нельзя передать в сборку.

## Состояния

Заказ: «Новый» → «Оплачен» → «Собирается» → «Отправлен». Дополнительный переход: «Новый» → «Отменён».
Попытка оплаты: «Ожидает» → «Успешна» либо «Отклонена».
Письмо: «В очереди» → «Отправлено» либо «Ошибка».

Пока результат оплаты неизвестен, резерв сохраняется, отмена и новая попытка оплаты блокируются. Система сверяет результат с платёжным сервисом; после окончательного отказа отмена снова доступна. Неопределённый результат нельзя считать отказом по одному тайм-ауту.
